# 手机镜头与点糖邀请

用户确认方向：双指缩放/旋转、视角复原、轻点地上糖邀请、低跳赶路后高跳压落。沿用真实接触包裹与已有手动塞糖，不加入吸引力、连续侧压或空中追踪修正。

## 实现顺序与边界

1. TouchOrbit 记录所有画布触摸，第二指安全取消原抓取并接管镜头。托盘起手同样登记；两指都离开前不回到单指抓取。窗口失焦、取消与捕获丢失均清理。
2. 落地糖轻点预留输入，5px鼠标/8px触摸阈值后才抓取。400ms内轻点给一个淡地面圈并邀请；拖动/取消不邀请。糖的独立刚体与材质持续复用。
3. 自动发现留1.2秒安静时间；邀请直接注意，0.32秒发现、0.45秒确认。重复点击不重启飞行。真正拿起糖或抓身体仍立即中断。
4. 距落点超过2.2单位时，用至多1.55单位的低跳赶路。靠近后0.43秒蓄力、高跳压落。每跳仅一次起跳冲量，空中由重力/阻尼负责；沿用0.42体宽的圆肩接触区，真实碰撞才开始包裹。
5. 蓄力、飞行、落地分别用努力/开心/满足表情；邀请后短暂看向用户。碰糖后的表情仍交给实际包裹/吸收进度。
6. 手机默认俯角0.23，缩放距离0.65–1.5倍。滚轮与双指均可缩放。手动转镜头期间暂停自动取景两秒，保留高跳自动取景。视角复原不重置身体、糖或颜色。

## 验证

- 5个方向的刚体、软体、实际接触、包裹和完整消化通过，包括远处邀请后小跳→高跳。
- 原有方糖/圆糖手动压入、撤回、松手进入，低腹支撑包裹及颜色交接回归通过。
- 事件测试覆盖托盘起手、同步/延迟捕获丢失、两种抬指顺序、重复接管、失焦清理；预留与实际拖动分别验证。
- 390×844与320×740浏览器尺寸检查属于响应式验收，不代替真实手机触摸或GPU性能测试。
- 已确认的模型、凝胶/眼睛材质、光学厚度与灯光模块不改。

不在本次范围：多糖、混色、连续靠近侧压、大范围流体模拟。
