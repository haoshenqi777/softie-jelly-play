## 1. 先守住可爱感

- 保留现在的半透明粉色果冻、细气泡、黑豆眼和小嘴。表情变化先由眼神与眼皮表现，再带动脸颊、身体。
- 张嘴最大高度约为单只眼睛的 70%，微笑与张口只出现一种轮廓。糖是无糖纸的小颗实体：圆角软糖或椭圆硬糖，常规大小约半只眼睛，不用大嘴吞大糖。
- 移动以整体小跳为主，先蹲下、起跳、落地压扁，再恢复。侧向探身只覆盖最后一点距离，保持圆轮廓。
- 转头以视线、轻微体态朝向表达；脸跟着皮肤一起挤，不把眼睛、嘴独立甩出身体。
- 鼓气时更高、更饱满，但底部仍有接触面积。目标不是一个硬球，而是一团憋着气、还能揉的软肉。
- 图中比例、幅度和时长都是待确认的设计目标。静态图用来确认角色与关键姿势，不能证明最终物理手感或帧率。

## 2. 喂糖：手里、空中、桌面，三种情况

### 糖本身就是可玩的物体

糖从拿出到落地始终是同一个立体物体。有厚度、背面、倒角、旋转和与高度对应的影子；经过身体时能被正确遮挡。手里拿着时也不是贴纸，松手后不切换成另一张图。

| 糖的种类 | 外形与材质 | 落地与碰撞 | 拿起来的感觉 |
|---|---|---|---|
| 软糖 | 半透明薄荷绿、淡紫圆角小方块，略有胶质感 | 触地处压扁、横向微鼓，一两次较低回弹后停稳；碰到其他糖会轻推、变形 | 抓取处先跟手，主体略滞后；释放后有小幅衰减晃动 |
| 硬糖 | 蜜黄色、淡桃色椭圆糖粒，有圆润切面与清晰高光 | 保持形状，反弹更高，会翻滚、碰开其他糖，受摩擦慢慢停下 | 完整刚性旋转，释放方向与手势速度一致 |

- 糖有重力、质量、线速度和角速度；落地、糖碰糖、糖碰身体都产生接触反馈。软硬差别来自运动与变形，不能只靠换颜色。
- 身体被糖轻碰时局部凹一下，再带出一小圈波动；糖很轻，不会把整只史莱姆撞飞。
- 慢慢放下就是轻放，快速甩手就是抛。软糖飞行中保持小幅拉伸和旋转，硬糖转动但不形变。
- 接近地面的糖有紧贴的影子；离地越高，影子越散。多颗糖可以互相遮挡、碰撞、堆在一起。
- 点击右侧糖果可拿出或放下一颗；拖出糖果会抓住这颗实体。进食时右侧仍可继续拿糖、投糖。地上的糖也可以再次拿起、扔出或放回托盘。
- 首轮以至少约 30 颗同时保留、可抓取、可碰撞为性能验证目标。已经静止的糖进入物理休眠，碰到或拿起再唤醒；不靠自动删除剩糖来假装支持多颗。具体容量须在真实浏览器验证。

### 手势约定

| 你的动作 | 糖的行为 | 它如何理解 |
|---|---|---|
| 点击色糖 | 在旁边放下一颗实体糖；可以连续点击 | 有人请我吃 |
| 按住糖，慢慢递近 | 糖仍在手里，跟着手走 | 盯住 → 期待 → 小幅探身 |
| 带着速度松手 | 沿松手方向飞出，受到重力影响 | 看飞行方向 → 预测落点 → 去接 |
| 慢慢松手 | 按软硬材质落地，压扁或翻滚，慢慢停下 | 看着糖落下 → 饿时靠近捡吃 |
| 仍按着，拖回色糖区 | 糖回到托盘 | 已经期待时，失落并鼓气 |
| 递到嘴边后明显拿远 | 手里的糖仍然存在 | 扑空、停一下、再看你 |

“抛出去”在松手时成立，不计作“收回糖”。只有它看见糖、明显期待了约半秒后再收回，才触发小脾气，避免选糖、普通移动也被误判。

### A. 接得住：有准备的小跳

1. **看见**：视线先锁糖，两个豆眼稍微抬起，身体静一下，约 0.15–0.25 秒。
2. **准备**：按糖的轨迹决定起跳方向，蹲低约 8–12%，底部接触面变宽。
3. **小跳**：整个身体离开桌面，影子留在桌上并变淡。空中保持圆润，脸朝糖。
4. **接住**：嘴与糖碰到才咬住。糖的冲量带来轻微后仰和肉感波动。
5. **落地**：底部压扁、上半团稍晚跟上，脸短暂挤眯，再进入咀嚼。

能否接住由实际距离、速度、起跳时机和接触决定。轻抛应容易成功；太快、偏太远就落地，不安排每次必中的表演。

### B. 没接住：自己找、自己捡

1. 糖按材质压扁轻弹，或弹跳翻滚，受到摩擦后逐渐停下；小影子始终对应其高度。
2. 它先看糖，再看地面；一个小跳靠近滚动终点。
3. 到旁边后蹲低，用下半团软肉**轻轻拱一下**，把小糖顶到嘴边高度，再含住。
4. 糖如果又滚了一小段，它会转移视线、补一次靠近。不会隔空吸糖，也不拉出长嘴或伸出手脚。
5. 糖接近可玩区域边缘时轻弹回来，避免追出画面。场景可以同时留下很多颗，嘴里一次只含一颗。
6. 还饿时优先选附近、能到达、较稳定的一颗；锁定后先完成这次靠近，避免视线和身体在一堆糖之间来回抖动。
7. 别的糖仍继续运动、碰撞。选中的糖被拿走，就看向手，停一下，再从剩糖里选择。连续投糖不会打断正在咀嚼的那一颗。

这次先在当前镜头的可玩桌面范围内完成糖的轨迹和接触。把史莱姆本人向屏幕前后拖近、扔远仍是后续空间玩法。

### C. 吃到以后：咬、嚼、咽、满足

- **咬住约 0.35–0.5 秒**：小小的“啊呜”，糖与嘴有真实接触；糖从前表面逐渐进入，被嘴沿与身体遮住，外露部分越来越小。不能到嘴边就突然删除、替换成腹内色球。
- **三次咀嚼约 1.8–2.3 秒**：左腮 → 右腮 → 两侧轻收；后一下稍慢。嘴闭合成小短弧，眼睛逐渐笑眯。脸颊只做柔和连贯的局部起伏；糖在表层后面只隐约可见，随挤压变软、轮廓淡掉，不出现外挂圆球。
- **吞咽约 0.45–0.7 秒**：嘴下方到上腹有一段很浅的软组织起伏向下传，脸颊回落，身体短暂收紧再放松。糖色随吞咽进入下腹，经过厚胶质与折射后自然更模糊。没有大亮球、直线输送带或可见管道。
- **腹内晕色约 2.5–4 秒**：腹部深处先出现一小缕低饱和糖色，近似透明糖浆在果冻里被轻轻揉开。几条细薄、不规则的色丝随身体惯性拖曳、弯曲，边缘渐渐融进胶质；不使用圆形扩散遮罩、整片亮色贴图或发光爆开。图示瞬间只占腹部很小一块，随后才扩大染色范围。
- **整身染色约 4–6 秒逐步完成**：可以与满足、下一颗糖的准备重叠。深处先染，厚薄不同处变化不同，原色逐渐混合到新的糖色；表面高光、透光边缘、气泡层次持续存在，避免匀速把整个身体换成一种平色。
- **满足约 0.7 秒**：眼睛弯起、身体松软，轻轻弹一下。不同糖主要改变颜色，暂不增加味道数值或奖励系统。

这段需要保持三层空间关系：最前面的外皮与高光、中间若隐若现的糖色、前后错开的气泡。糖色始终在身体内部，并跟着身体变形与晃动；不盖在脸上，也不在角色移动时留在屏幕原位。软糖内部痕迹更柔，硬糖先留一点微小折光后再淡开，两者共享克制的美术风格。

连续吃不同颜色时，保留前一颗尚未散尽的少量底色，新糖只从新的吞咽开始，柔和混合；不会每吃一颗就重置全身颜色或叠加亮度。下腹饱满程度只在吞下后平滑增加，与局部染色分开控制。

动画验收专门包含：正常速度看“入口—嚼—咽—晕开”的因果；逐帧看糖是否穿过脸或瞬间消失；边晃身体边看内部糖色是否跟随；连续三种糖看混色是否发灰、发白或过亮。近景图只能确认质感方向，时长、遮挡与层次必须通过实际连续画面确认。

### D. 吃饱了就停，糖不跟着消失

- 吞下之后才增加饱腹感，扑空、碰到糖、含住尚未吞下都不计入。先以约 6–8 颗普通小糖吃饱作为调参起点，大一点的糖增加更多；最终用试玩节奏确定。
- 快吃饱时，靠近速度略慢，嚼得更悠闲，吞完有一次轻轻的腹部起伏。饱了以后完成嘴里这一口，然后停下，不继续挑选地上的糖。
- **吃饱的姿态**：腹部向下和两侧圆起来，底部更宽，身体略低；弯眼、小闭嘴，像软布丁一样轻轻晃。仍能摸、按、提起来，有重量和局部肉感。
- 再递到嘴边：先看一眼，闭着小嘴，整个身体轻轻偏开，再抬眼看你；不是突然变生气，也不会让糖穿进嘴里自动消失。
- 再扔糖：它可以看、眨眼，被碰到会有正常受力反应，但不主动起跳接食。糖继续落地、碰撞，剩下的都留着。
- 饱腹与情绪独立：吃饱了仍能被抚摸哄开心，也能玩泡泡；已经不想吃时收回糖，不触发“不给我吃”的委屈。
- 先以约 1–2 分钟后逐渐恢复一点食欲为调参起点；恢复后先睁眼看看附近，再主动找一颗。满腹时也可以安静入睡。页面切到后台时暂停这段行为计时。
- 不把饱腹做成照顾任务，不要求定时喂养。界面主要靠体态和表情告诉玩家“我吃饱啦”；不增加显眼数值条。

| 状态 | 轮廓与表情 | 物理手感 |
|---|---|---|
| 生胖气 | 吸气后略高、两侧饱满，眼睛斜眯，小倒弧嘴 | 内部压力增加，浅按就有撑住的感觉，松手回弹较有劲 |
| 吃饱 | 下腹低低圆起来、接触面宽，笑眯眼、闭嘴 | 重心略低，仍软糯，腹部慢半拍回晃，不等同于提高硬度 |

两种状态都不是单纯等比放大。吃饱用下腹与重心变化表达；鼓气用全身压力与姿态变化表达。所有参数都保留可调范围，以实际可爱程度与连续手感为准。

## 3. 收回糖：会“生胖气”，但可以哄

| 事件 | 表情与身体 | 持续与下一步 |
|---|---|---|
| 第一次拿走 | 眼睛跟着糖，嘴角往下，身体向前一小下后收回 | 失落停留约 0.5 秒 |
| 发现真不给 | 吸一口气，腹部先饱满，再传到两侧和头顶 | 用约 0.8 秒鼓起来 |
| 鼓气完成 | 高度、宽度温和增加约 10–12%，眼睛眯成有角度的豆眼，小小倒弧嘴 | 看开一点，又偷偷瞟糖 |
| 短时间又逗一次 | 多一点鼓腮，轻轻跺一下软桌面 | 有上限，不无限膨胀 |
| 什么都不做 | 脾气慢慢过去，轻轻呼气，逐渐变软 | 约 8–12 秒恢复 |
| 慢慢摸 1.5–2.5 秒 | 先偷看 → 眼角放松 → 消气 → 靠过来 | 最后冒一颗很小的爱心泡泡 |
| 饿着时再递糖 | 先迟疑看一眼，再去吃 | 不长时间拒食、不惩罚玩家 |

一次收回只记一次反应，约 4 秒内不会重复叠加；气鼓鼓程度最多两档。它有一点小脾气，但仍愿意继续和你玩。

### 鼓起来以后，手感怎样变化

把鼓气理解为胶质外层里憋进了一点空气：胶质的量保持不变，形状更饱满，内部压力让它更撑。实现时以近似软体与压力反馈表达，不能只把整个模型等比放大。

| 操作 | 应看到与摸到的反馈 |
|---|---|
| 单点按 | 接触处先凹下去，周围、另一侧温和鼓起；越按深越有阻力 |
| 轻轻戳 | 局部凹陷后弹回，波动传过身体；它短暂单眼眯起，仍鼓着气 |
| 拖住一侧 | 抓取点先受力，身体重心随后移动；拉到一定程度阻力增大 |
| 触屏双指夹两侧 | 两侧凹下，顶部和前后方向鼓出，眼距随皮肤挤压 |
| 松手 | 先略微弹过头，再衰减晃动约 0.8–1.2 秒；轮廓不瞬移 |
| 提起再放下 | 重心下落，接触桌面后压扁，随后回弹；影子跟随高度和落点 |
| 温柔抚摸 | 随着消气，抵抗感逐渐下降，变回原本糯软的状态 |

桌面约束、局部受力、受压后的体积分配、惯性和阻尼共同决定形变。脸使用同一表面运动；受压时产生眯眼、歪嘴，但不会脱离身体。气鼓鼓并不使它失去重量或自动浮空。

## 4. 之前四个想法，具体怎样玩

### ① 喂糖成为招牌动作

上面的“递、抛、接、捡、吃、吃饱停下”构成完整玩法。每颗糖都是独立可追踪的物体，支持多颗同时存在；颜色变化是吃到后的结果。没有咬住之前都能继续拿起或影响它，一次只吃一颗。

### ② 分得清抚摸、按压和欺负

- **慢扫**：移动温和、方向连贯，约半秒就有舒服的眯眼；继续摸会靠向手。
- **按住不动**：是揉压，局部凹陷、被压那侧眯眼，不自动累计生气。
- **正常拖动**：是提起或搬动；空中略惊讶，落地短暂挤眼，不算欺负。
- **短时间连续三四次戳**：先惊讶，再委屈，最后小幅鼓气。一次轻戳不会立刻翻脸。
- **重新慢摸**：优先回应安抚，先松开眼角，再放掉身体的气，情绪有过渡。

### ③ 用可戳的泡泡表达

- 连续温柔抚摸约 2 秒：头顶慢慢冒一颗小爱心泡泡，先轻晃再飘走，约 3 秒消散。
- 落地冲击较大：出现两颗淡淡星星泡泡，配一小段晕乎表情，约 1.2 秒恢复。
- 鼓气被哄好：呼出一个小圆泡，泡里短暂浮现爱心。
- 泡泡能被点击戳破：缩一下再“啵”地消失，附近小泡轻微晃动，史莱姆朝声响看一眼。
- 同时最多两颗主要泡泡；泡泡在身体轮廓外，避免挡住脸或抢走揉捏操作。
- 音效默认安静，提供开关。打开后才有轻微的接糖、软落地、泡泡声；音量与冲击强度有限关联，不突然炸响。

### ④ 没人理时慢慢犯困

- 安静约 35–45 秒：眨眼变慢，眼皮略低，头顶软下来；不弹提示打断玩家。
- 继续安静到约 60 秒：用约 3 秒缓缓趴低，体积向周围摊开，保持胶质的量。
- 睡着后：身体只有很轻的呼吸起伏，嘴边一颗透明“睡泡”随呼吸涨缩。
- 轻点唤醒：睡泡破掉 → 身体抖一下 → 一只眼先开 → 两只眼看你 → 装作没睡，约 1 秒。
- 糖靠近也会引起注意：还饿时睁眼看糖，醒过来后再接近；吃饱时半睁眼看看，闭嘴继续歇着。
- 拖动、飞行、进食、鼓气过程中不进入睡眠；切换浏览器页面后不累计突然的大动作。

| 表情 | 眼睛 | 嘴 | 身体 |

| 放松 | 黑豆眼，偶尔眨眼 | 小 U | 稳稳坐着 |
| 好奇 | 一侧稍睁大，先看目标 | 小短弧 | 轻歪一点 |
| 期待 | 视线抬起，眼睛精神 | 小小开口预备 | 稍立起来 |
| 啊呜 | 注视糖 | 小 O | 小跳、轻探 |

## 6. 审稿重点与实施顺序

请先确认四张图里的关键点：**小嘴比例、鼓气后的饱满程度、被按后的凹陷轮廓、糖的实体质感、吃饱与生气的区别，以及腹内晕色是否细腻**。再看接糖与落地捡糖的动作是否符合你想要的小生物。材料图的软硬糖使用特写尺度，实际喂食仍用能装进小嘴的小糖。腹内效果以新近景分镜为准，前两张里的吞咽色块只作为动作位置示意。

认可后建议分两轮实施：
1. 多颗实体软硬糖、投掷与碰撞、接/捡/吃饱停下、收回后的鼓气、可揉的鼓气手感，以及这条流程用到的表情。
2. 爱心/星星泡泡、轻音效、困倦/睡泡/唤醒，以及四种行为间的衔接。

每轮都以真实浏览器里的连续动作验收：身体与脸贴合、轮廓可爱、事件因果清楚，再检查帧率。不会仅凭静态效果图判定动效完成。继续使用 Three.js 与严格 WebGPU 渲染，不改成 WebGL。

第一轮的具体验收场景：连续扔约 30 颗，检查软糖受压与硬糖滚动、糖之间碰撞、与身体碰撞、地面停稳和再次抓取；观察它一次只选一颗吃；吃饱后再扔，确保仍有物理反馈但不继续吞食；收回它期待的糖后出现可揉的鼓气，而吃饱后收回不生气。性能在真实浏览器前台、约定窗口大小下记录，目标 60 帧，不能以静态图或单只史莱姆的旧数据代替这轮验证。
