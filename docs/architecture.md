# 架构与控制权

## 应用边界

React 页面承载设置、托盘与状态展示；Three.js 场景管理持续运行的交互和渲染。vinext 在构建时预渲染页面，浏览器执行玩法，不依赖线上应用服务器。运行与部署命令见 [README](../README.md)。

主页面通过 `createStudio` 创建场景，使用 `StudioHandle` 修改设置、传递操作并释放资源，场景通过回调返回加载、进食、行为等状态。高频模拟数据留在场景和模拟对象内，避免逐帧经过 React 状态传递。

## 主要协作关系

| 层 | 主要职责 | 边界 |
| --- | --- | --- |
| 页面与面板 | 用户设置、托盘输入、状态显示 | 不实现物理求解 |
| `studio-scene` | 场景生命周期、镜头、输入协调、渲染 | 组合模块并管理资源 |
| `VolumeInteraction` | 连接软体、抓取、行为和表面 | 将意图转为模拟操作 |
| `CharacterBehavior` 与 motor | 选择行为目的并执行运动 | 意图受真实接触与姿态约束 |
| `VolumeSoftBody` | 节点运动、体积约束、抓取和地面接触 | 不依赖 React |
| `StudioCandies` 与 `GameIntake` | 糖果实体及进食表现协调 | 保持实体身份和颜色连续性 |
| `BodyIntake` 与接触模块 | 包裹、进入、封合和吸收进度 | 以模拟接触为依据 |
| 材质与光学模块 | 表面、内部糖色、气泡与光学表现 | 消费模拟状态，不替代物理结果 |

## 输入与动作

指针事件先确定身体、糖果或镜头的持有权。移动输入按每帧每指针的最新位置合并，释放时提交最后位置，取消时清理待处理移动。

镜头接管必须取消原操作，多指结束顺序、同步或延迟的捕获丢失都不能把事件交给错误对象。抓取、进食与自主运动需要协调，不能让多个模块同时争夺身体位置。

行为层请求方向与动作，运动层和求解器决定实际运动。起跳通过有限冲量启动，飞行由重力和接触推进；不要逐帧写位置来伪造接近。

## 模拟到画面

软体笼驱动渲染表面，脸部和接触锚点跟随同一材料空间。糖从外部接触到内部溶解保持身份，`GameIntake` 协调实际接触进度、可见糖和染色场，避免物理完成与画面完成脱节。

WASM 加速局部数学计算，TypeScript 仍负责整体交互与模拟协调，详见[物理文档](physics.md)。材质近似与移动端采样见[渲染文档](rendering.md)。

## 生命周期

场景拥有监听器、动画回调、模型、材质、纹理、光学目标和模拟对象。复位需同时处理手势、糖果和行为状态；卸载应移除监听并释放资源，GPU 时间戳读回与销毁要正确排序。

页面隐藏时暂停或限制模拟推进，恢复时避免把后台时间一次性补成大步长。持有权不能跨失焦残留。

## 样片与兼容代码

主玩法以 `app/softbody` 和 `studio-scene` 为入口。`app/lookdev` 提供局部机制观察；仓库中的 `slime-*` 模块部分被复用、部分用于独立或旧机制。判断归属应追踪当前导入链，不按命名推定它们都是主路径，也不把旧机制说明当作当前架构。
